# annotations — the additive-table convention

**Shipped tier data is never mutated.** Not a value, not a column, not a row. Every package
ships with `CHECKSUMS.sha256`, its `condition` and provenance columns underpin published
statistics, and the POTS corpus already carries the scar of a column whose meaning differs
between tiers (`ontology_id_source == 'unresolved_nulled'` means *id kept* in one tier and *id
nulled* in another; the obvious filter silently drops 2,242 valid rows). Editing a shipped
column in a later version manufactures exactly that.

New information about shipped rows — a relabel, a re-checked quote, a bucket verdict, a
retraction notice — ships as a **separate table** in `annotations/`, joined on a stable key:

- **`pmid`** for paper-level facts (a paper's studied population, its scope verdict);
- **`row_idx`** — the 0-based position in the tier's shipped `*_findings.parquet` — plus `tier`
  for finding-level facts. `row_idx` is stable because the shipped file is frozen; if a package
  is ever re-versioned, the annotation table is regenerated by script against the new file and
  says so in its `basis` column.

Every annotation table carries, on every row: who decided (`basis` / `classifier`), against
which definitions version, and when. Every rate derived from an annotation table is reported
with numerator, denominator and basis, and with the negative control that was run.

Rows that are NOT covered by an annotation table are absent from it — never filled with a
default. A reader joining `left` sees `NaN` and knows the row was not assessed.

## `condition_annotations.parquet` — pmid-keyed, population-studied semantics

Records the outcome of judging each paper's shipped `condition` label against the WRITTEN bucket
definitions (`config.condition.enum[*].definition`) under the decided semantics
(`config.condition.semantics = population`: `condition` names the patient POPULATION studied).

| column | type | meaning |
|---|---|---|
| `pmid` | str | join key; one row per assessed paper |
| `condition_as_shipped` | str | the label the tier data carries (copied, not edited) |
| `condition_specific` | str | free text, as the paper states it ("systemic mastocytosis", "idiopathic MCAS") |
| `condition_bucket_verdict` | enum | `in_bucket` \| `bucket_violation` \| `bucket_definition_disputed` \| `NEEDS_HUMAN` |
| `condition_population_kind` | enum | `disorder_population` \| `mechanism_only` \| `not_applicable` |
| `condition_suggested` | str \| null | the bucket the paper would belong to under the definitions, if different; a suggestion, never applied |
| `deciding_span` | str | verbatim span from the freshly fetched abstract that decided the verdict |
| `span_verified_verbatim` | bool | the span was found in the fetched text under symmetric normalization |
| `classifier` | str | `human:<initials>` or `model:<literal model id>` |
| `definitions_version` | str | `config.condition.definitions_version` the verdict was judged against |
| `assessed_at` | str | ISO-8601 UTC |
| `basis` | str | how the paper entered the table (census stratum, sample seed, or "full census") |

`bucket_violation` (the paper does not belong under the definition) and
`bucket_definition_disputed` (the definition itself is the open question) are distinct verdicts
and never share a value — one name never carries two concepts. `mechanism_only` is the
population_kind of the ~69% of the POTS `MCAS` bucket that studied mast-cell biology with no
mast-cell-disorder population; those rows keep `condition == 'MCAS'` in the tier data and are
read through this table.

Negative control to ship with it: a set of papers from an unrelated bucket run through the same
classifier (the POTS census used 15 migraine papers → 14/14 assessed `neither`).

## `quote_retrofit_<tier>.parquet` — row-keyed traceability against re-fetched source

Records, for each finding row, whether its `provenance_quote` can be found in source text
fetched **now** (as opposed to the text retained at extraction time, where that exists). It is
what makes a traceability rate publishable for tiers that discarded their source text.

| column | type | meaning |
|---|---|---|
| `tier` | str | `t1` … `t4` |
| `row_idx` | int | 0-based position in the tier's shipped findings parquet |
| `pmid` | str | copied for convenience; `row_idx` is the key |
| `source_kind` | enum | `refetched_fulltext` \| `refetched_abstract` \| `retained_archive` \| `no_source` |
| `source_fetched_at` | str \| null | ISO-8601 UTC of the fetch; null for `retained_archive` |
| `source_chars` | int \| null | length of the source compared against |
| `exact` | bool \| null | normalized quote is a verbatim substring of normalized source (`quote_trace.quote_traceability()[0]`) |
| `traceable` | bool \| null | exact OR shingle overlap ≥ threshold (`[1]` — the decision; never `bool()` the tuple) |
| `n_shingles` | int \| null | basis of the shingle decision (`[2]`) |
| `quote_has_entity_codes` | bool | the stored quote contains raw HTML entity codes (`&#x…;`); 128 POTS rows do — verbatim to what the model read, traced under symmetric normalization, never repaired |
| `normalizer` | str | `quote_trace.normalize@<version or checksum>` — both sides pass through it |
| `note` | str \| null | e.g. `prompt_truncated` (source exceeded the input cap), `abstract_shorter_than_quote` |

`traceable`, `exact` and `n_shingles` are null when `source_kind == 'no_source'`; such rows are
reported as `n_no_source`, never folded into a numerator or denominator. The table ships with
its wrong-paper negative control (quotes matched against a different paper's source; a working
matcher reports ~0%) and `comparator_symmetry_tests.py` must pass before the census runs.

## Producing an annotation table

1. Load the shipped parquet read-only; never write back to it.
2. Compute the annotation with `row_idx = range(len(df))` or `pmid` as the key.
3. Write `annotations/<name>.parquet` (+ `.csv.gz`), a `<name>.DATA_DICTIONARY.md` with the
   column table above filled for what was actually produced, and the negative-control result.
4. Regenerate the package `CHECKSUMS.sha256` **by script** (`build_packages.py`) — the tier files
   are unchanged and their hashes must come out identical; only the new files are added.

If a shipped parquet's own data dictionary and this convention disagree, the shipped data
dictionary describes what was actually built and is authoritative; update this file.
